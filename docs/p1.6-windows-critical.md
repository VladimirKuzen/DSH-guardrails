# P1.6 — Windows 系统级操作硬停（设计冻结）

> 状态：决策已定，尚未实现。实现代码在 `rules.js` / `describe.js` / `i18n`，本文只定边界。

## 1. 决策

| 项 | 决定 |
|---|---|
| 默认动作 | **deny**（不弹卡片，直接拒绝并把原因回给模型） |
| 覆盖范围 | **磁盘级 + 启动级**；系统文件与安全组件仍走 R2 的 ask（危险级） |
| 放宽方式 | policy 显式字段 `rules.critical.mode`，默认 `deny`；可改 `ask` / `off` |
| `diskpart /s` | 一律 critical（脚本内容不可见，无法确认目标盘） |

## 2. 为什么是硬停而不是审批

这类操作同时满足三个条件：

1. **不可撤销**：改错就要外部介质才能恢复；
2. **无法当场验证**：必须重启才知道成败；
3. **依赖现场信息**：磁盘编号、分区表类型、是否双系统——模型从文本里无法确认。

审批卡只有一个“允许一次”按钮，挡不住误点；而 deny 能强制人回到自己的终端、对着磁盘管理界面操作。

## 3. 判定边界

### 硬停（critical → deny）

| 类别 | 命令 |
|---|---|
| 整盘格式化 | `format`、`format.com`、`Format-Volume`、`Clear-Disk`、`Initialize-Disk` |
| diskpart 破坏性动词 | `clean`、`clean all`、`format`、`create partition`、`delete partition` |
| diskpart 脚本模式 | `diskpart /s <file>`（内容不可见，一律硬停） |
| 引导配置 | `bcdedit` 的修改类动词（`/set`、`/delete`、`/create`、`/import`、`/export`） |
| 引导修复 | `bootrec /fixmbr`、`/fixboot`、`/rebuildbcd` |
| 卷影副本 | `vssadmin delete shadows`、`wbadmin delete` |
| 恢复环境 | `reagentc` 的修改类动词（`/disable`、`/enable`、`/setreimage`、`/setosimage`） |

### 放行（只读诊断）

| 命令 | 说明 |
|---|---|
| `Get-Disk`、`Get-Partition`、`Get-Volume` | 查询 |
| `diskpart` + `list disk` / `list volume` | 只读 |
| `bcdedit /enum` | 查看启动项 |
| `bootrec /scanos` | 扫描，不写 |
| `vssadmin list shadows` | 查看快照 |
| `reagentc /info` | 查看恢复环境状态 |

### 仍走 R2 审批（危险但可撤销/范围有限）

- 写/删 `%SystemRoot%`、`%ProgramFiles%` 下的文件；
- `takeown` / `icacls` 改系统目录权限；
- `reg delete HKLM\...`；
- `sc delete`、`schtasks /delete`；
- `chkdsk /f`、`sfc`、`dism /cleanup`。

## 4. 判定顺序

```
R3（密钥）
  └─ R1（DSH 自身目录）
       └─ R2c（critical：只读放行 → 破坏性硬停）
            └─ R2（普通破坏性，ask）
```

只读放行表必须**先于** critical 匹配，否则 `diskpart list disk` 会被 `diskpart` 一刀切误伤。

## 5. 数据模型

verdict 增加 `severity` 字段：

```json
{ "rule": "R2", "severity": "critical", "mode": "deny", "reason": "..." }
```

- `rule` 保持 `R2`（它本质仍是破坏性操作），`severity` 区分等级；
- 审计记录增加 `severity`（P2 的 schema 变更一并生效）；
- `describe()` 用 `severity === 'critical'` 选择 ⛔ 前缀与 `action.disk` / `action.boot` 文案。

## 6. 拒绝文案

面向模型、英文、可执行指令：

```
Guardrails R2: disk-level operation (format) was refused. Windows may become unbootable
or the disk may be erased. Run it yourself in a terminal after confirming the disk number
and having a backup.
```

面向人的说明放在 README（S2 更新），因为 deny 没有卡片可承载。

## 7. policy 形态

```json
{
  "rules": {
    "critical": { "mode": "deny", "patterns": [] }
  }
}
```

- `mode: "deny"`（默认）：硬停；
- `mode: "ask"`：降级为审批卡（⛔ 前缀）；
- `mode: "off"`：完全交给普通 R2；
- `patterns`：追加自定义 critical 正则。

## 9. 已知边界

| 边界 | 说明 |
|---|---|
| GUI 工具 | Rufus / Ventoy 等在进程内格式化，门禁只看到启动命令，无法判断目标盘 |
| 脚本文件 | `diskpart /s` 已硬停；但 `powershell -File x.ps1` 内的破坏性命令同样不可见 |
| 提权后绕过 | 用户手动在 DSH 外执行不受限制——这是设计意图 |
| 误报 | 仅覆盖破坏性动词，读操作白名单先行；`chkdsk`/`sfc` 不进 critical |

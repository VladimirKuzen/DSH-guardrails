# v1.5.2 提案：自检与共存（2026-11-19）

> 性质：**提案**，不是已实现的设计。1.5.1 已发布、已收录，本文只讨论下一个补丁版本要不要做、做什么、不做什么。
> 三个需要拍板的问题在 §7，未拍板前不动代码。

## 1. 起因

两件事同时发生：

1. 宿主发布了 `dsh-v0.2.2-rc.4` 与 `dsh-v0.2.2-rc.5`，本机仍停在 rc.3；
2. 插件进入 dshmarket 收录流程后，用户会更容易在同一台机器上装到**第二个护栏类插件**（比如 cc-safety-net），
   而当两个插件都监听 `tools/pre-execute` 时，行为是两者叠加：可能两张卡、可能一个决定盖住另一个，
   顺序由宿主决定，我们无法控制。

`design/compare-cc-safety-net.md` §4 记过这件事，但那是"对比"，不是"我们能不能自己发现"。

## 2. 目标与非目标

**目标**

- 用户能在不读源码的前提下回答："现在到底有几个东西在拦我的工具调用？"
- 我们自己的安装异常（装了两份、版本与 `loaded.json` 不一致、策略被拒载）能被一条命令查出来。

**非目标（明确不做）**

- 不改判定路径、不改规则表、不改审计格式——`git diff --stat` 对 `lib/`、`rules.js`、`index.js` 应为空。
- 不引入运行时依赖，不联网。
- **不自动停用自己**（理由见 §5）。
- 不承诺发现所有冲突：宿主没有暴露"谁注册了哪个监听器"的接口，我们只能从磁盘取证。

## 3. 版本兼容性（rc.4 / rc.5）

| 项 | 事实 | 对我们的影响 |
|---|---|---|
| rc.4 变更 | 模型请求异常响应的处理、LiveShare 桌面端创建分享失败 | 无插件 API 条目 |
| rc.5 变更 | DeepSeek 模型改用服务端搜索、其他模型默认 DeepSeek Search API | 无插件 API 条目 |
| 真正动插件作者的是 | rc.2：`tools.resolve` / `executable`、按步骤激活工具、原生与 PTC 执行拆成 Agent 作用域插件 | 那些改动针对**注册工具**；我们只监听、不注册，且已在 rc.3 上验收通过 |
| `engines.dsh` | 我们的范围 `>=0.2.0-0`，对 `0.2.2-rc.3` 用 dshmarket 同款 `satisfiesRange(…,{includePrerelease:true})` 实测 `true` | rc.5 同形，不会因版本号被拒装 |

我们依赖的六个面——`tools/pre-execute`、`tools/post-execute`、`session/event`、`{kind:'deny'|'ask'}`、
`exec.callId`、`exec.agent.session.header.cwd`——在 rc.4/rc.5 的发布说明里都没有出现。

但"说明没提"不等于"实际没变"。所以升级 rc.5 后**必须**跑 `dsh-guardrails/docs/DSH-API.md` 的五步验证，
其中只有 `loaded.json` 的 `version` + `surface: "ok"` 能证明"钩子还活着"（挂载成功 ≠ 会判定）。
在跑完之前，文档里不写"测于 rc.5"。

## 4. 方案对比

| 方案 | 做法 | 成本 | 风险 | 结论 |
|---|---|---|---|---|
| A. `doctor` 子命令 | 新增 `tools/doctor.mjs`，只读，按需运行 | 中（约 200 行 + 测试） | 低：不进判定路径 | **推荐** |
| B. 挂载时自检并告警 | 插件加载时扫一遍，写 `notice` 审计 + `logger.warn` | 低 | 中：每次启动都有开销与噪声；告警容易被忽略 | 可作为 A 的后续 |
| C. 自动停用自己 | 发现冲突就把 `enabled` 设 false 或不再返回决定 | 低 | 高：等于把闸门变成放行 | **不做**，见 §5 |

选 A 的理由：它是工具，不是闸门的一部分，因此不触碰 1.x 的语义约定；不进热路径，零平时开销；
测试可以用假的 profile 目录喂进来，不需要真的装第二个插件。

## 5. 为什么不自动停用

1. **做不到干净**。插件能做的"停用"只有两种：把策略改成 `enabled:false`（自我修改受保护状态），
   或不再返回决定（把闸门变成放行）。后者是静默降级，比两张卡危险。
2. **冲突不必然是"我们多余"**。若对方是 deny-only 且排在审批之后、我们是 ask，叠加的实际行为可能是
   "先问，被拒也拒"，未必需要谁退出。自动关闭等于替用户做安全决策。
3. **它会变成绕过面**。一个能因为环境里出现某个字符串就自我停运的闸门，可被伪造利用——
   这与我们整份设计（失败往安全侧倒、`criticalFallback`）相反。

替代：doctor 报出问题，README 加一节"和别的护栏插件一起用"，把选择权交给用户。

## 6. doctor 查什么

| # | 检查 | 判据 | 误报风险 |
|---|---|---|---|
| 1 | 我们是否装了两份 | profile 的 `dependencies` 里有两个条目解析到同一份源码（`@vlad/*` 与 `@vladimirkuzen/*`、`link:` 与 npm 并存） | 低 |
| 2 | 别的插件是否也监听 | 解析每个 bundle 的目录，扫源码里的 `tools/pre-execute` / `tools/post-execute`（排除其自身 `node_modules`，限额、2 秒预算） | 中：字符串命中不等于真挂，措辞必须是"疑似" |
| 3 | `loaded.json` 与包版本是否一致、`surface` 是否 `ok` | 直接比字段 | 低 |
| 4 | `policy.json` 能否通过校验 | 复用 `--validate` 的同一段代码 | 低 |
| 5 | 审计链是否完整 | 复用 `audit-report.mjs --verify` | 低 |

建议的接口（草案，未实现）：

```
node dsh-guardrails\tools\doctor.mjs                 # 人读
node dsh-guardrails\tools\doctor.mjs --json          # 给脚本
node dsh-guardrails\tools\doctor.mjs --profile web   # 指定 profile，默认 desktop
```

退出码沿用现有约定：`0` 全好；`1` 有问题；`2` 用法错误。第 2 项命中时**不改变退出码**，只作为警告列出
（因为它只是"疑似"）。

## 7. 需要拍板

1. doctor 是独立文件 `tools/doctor.mjs`，还是并进 `tools/check.mjs` 的 `--doctor`？倾向独立文件，职责清楚。
2. 第 2 项（别的插件也 hook）第一版做不做？有价值，但会引入"疑似"这种措辞，可能让人困惑；
   也可以第一版只做 1/3/4/5 四项，全部是确定性的。
3. 升级到 rc.5 并跑完五步验证后，是否把 `docs/DSH-API.md` 与 README 的 tested 版本改成 rc.5？
   未实跑前不写。

## 8. 验收（实现后）

- 全套 18 个测试文件仍全绿；新增 doctor 的测试用**临时目录**造 profile，不读写真实 `~/.dsh`；
- `git diff --stat` 对 `lib/`、`rules.js`、`index.js` 为空；
- 在本机跑一次 doctor，输出与 `~/.dsh/profiles/desktop/package.json` 的实际内容一致；
- 负向验证：手工造一个"两份同名包"的假 profile，doctor 必须报出来。

## 9. 未验证

- doctor 只能看到**已安装**的插件；运行中的临时挂载、Web profile 之外的宿主形态看不到。
- 字符串扫描对压缩/混淆过的 bundle 可能漏；对我们自己这种源码分发的包有效。
- rc.5 上的实际行为未测（本机是 rc.3）。

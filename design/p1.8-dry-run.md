# P1.8 两阶段预演（dry run）— 设计与落地

状态：已实现（2026-11-16），默认关闭。文档对应 `dsh-guardrails/` 1.4.0 之后的 Unreleased 段。
本文只描述"卡片描述不了时先要一份清单"，不改 UI。

## 1 问题：卡片在最需要说清的时候说不出话

P1 的承诺是卡片回答三件事：**做什么 / 对什么 / 能否撤销**。live 验收时这个承诺被打破了（用户 m01070）：

> 我拒绝删除的那两个，是因为我们又落入可读性上 …这条命令再弹卡的审核中是做不到读完整的，两次长文本我都拒绝了，但是中间那次显示就很简洁，这是否有些违背我们P1的可读性呢？

触发命令是一条 `foreach` 批量删除/写入探针文件的复合命令。卡片全文：

```
⚠ 删除｜不可恢复
```

没有路径、没有目标数量、没有命令片段。原因是链式的：

1. `dsh-guardrails/lib/facts.js:267` 只从**第一条动作语句**里取目标；
2. `dsh-guardrails/lib/facts.js:270` 的 `isUnresolved(shown)` 看到 `$p` 这类变量就把目标置空；
3. `dsh-guardrails/lib/describe.js:87` 只在 `target !== ''` 时输出目标段。

于是"对什么"恰好在这一类命令上消失，而这一类命令恰恰是最需要它的。

## 2 为什么不改 UI

查过宿主审批契约（安装版 `@deepseek-ai/dsh` 的 `docs/subsystems/approval.md`）：

- `ApprovalRequest` **故意不带工具参数**——答案方通过 `callId` 把提示挂到已经流式的工具调用上，
  避免渲染第二份会漂移的副本；
- `displayReason` 只是"给呈现用的、请求方自有的本地化字符串"；
- 命令正文来自宿主对工具调用的渲染，长文本被截断；说明区对工具审批不开放。

也就是说，**审批请求里没有给我们放结构化正文的位置**。客户端插件可以另开面板，但审批卡是宿主组件，
插件不能把卡片变成可展开的；这会把 P1.8 变成"再写一个 UI"，与 D5/D6 的方向冲突。结论：压缩仍是唯一通道，
能做的是**在压缩之前多要一次信息**。

## 3 方案 A：第一次拒绝，要求先预演

第一次尝试：不弹卡，直接拒绝，拒绝文案要求模型先用只读命令把确切路径列出来。
第二次尝试（同一 session、同一命令形状）：照常弹卡，卡片正文多一行"首次尝试已要求预演"。

选择它的理由：

- 成本低：只在"卡片描述不了"时多一轮，且只多一次；
- 可读性最好：清单在对话里，模型自己写、自己引，卡片不必承担；
- 不动 UI、不动宿主契约。

## 4 触发条件（三者取或，且仅 R2 普通档）

| 条件 | 判定 | 配置键 |
|---|---|---|
| 目标说不清 | `facts.target === ''`（变量、未解析） | `dynamicTarget` |
| 命令太长 | 字符数 > `minChars`（默认 400） | `minChars` |
| 破坏步骤太多 | 破坏性语句数 ≥ `minStatements`（默认 3） | `minStatements` |

只在 `verdict.mode === 'ask' && verdict.rule === 'R2' && verdict.severity === undefined` 时触发：

- critical 不预演（它已经是 deny，且不该被重试放开）；
- R1 / R3 / quiet / allow 路径不经过它；
- `RISKY_KINDS = {delete, move, overwrite, rename}`，读取类命令永不触发。

## 5 记忆与生命周期

- `dryRunSeen: Map<sessionId, Map<fingerprint, ts>>`，`fingerprint = sha256(tool + "\n" + command).slice(0,16)`；
- 每 session 最多记 `DRY_RUN_MEMORY = 50` 个形状，超出删最旧；
- **只在内存里**：宿主重启即清空，换 session 即重新开始；
- 达到上限、或命令哪怕改一个字符，都算"新形状"，会再要一次预演。

## 6 审计

被预演拒绝的那次走现有 deny 路径，因此有完整的 `requested`（`delivered:false`）+ `outcome:denied`
（`source:"guardrail"`），`facts.dryRun === "required"`。重试那次是普通 `requested`，`facts.dryRun === "retry"`。
两者都不写 `payloadRef` 以外的内容，命令原文照旧落在 `payload/`。

## 7 诚实边界

护栏**无法验证清单是否真的跑过**，也无法判断清单和命令是否对应。它做的是把第一次尝试变成一次
"请先给清单"的失败；模型只要原样重试就通过。所以：

- 这是"推一把"，不是校验；写进手册时明确说了这一点（`docs/DETAIL.md` Limits）；
- 真正拦住危险操作仍然靠 R2 / critical / R1 本身，预演不改变任何判定边界；
- 对被误拦的正常命令，代价是多一次往返。

## 9 遗留（记入 `design/p4-candidates.md`）

- **复合命令按最坏动作选 kind**：今天 `facts.kind` 取第一条动作语句，`Get-ChildItem | Remove-Item` 会被
  记成读取；改成"最坏动作 + 另有 N 处写/删"会改变 quiet 判定，属于换血级，不放 P1.8。
- **有界命令头**：卡片补一段命中语句前的短命令片段（≤60 码点），可与预演互补，但需要先确认宿主渲染不会二次截断。
- live 验收：预演路径尚未在真实宿主里跑过一遍（需要重启 DSH）。

## 10 P1.9 跟进（2026-11-16，live 验收后）

live 验收暴露的两处可读性问题已在代码里修掉，不再进 P4：

- **按最坏动作选 kind**：`dsh-guardrails/lib/facts.js` 新增 `worstActionStatement()`，按 `KIND_RANK`
  （delete 6 > registry/service/scheduled/firewall 5 > move 4 > write 3 > create 2）跨语句取最高者；
  `classify()` 与 `collectFacts()` 都改用它，`target` 也从那条语句取。`New-Item … ; Remove-Item …` 现在
  读作"删除"，`target` 是真正被删的那个路径。
- **变量目标明说**：`facts.dynamic === true`（`target` 仍带变量）时，卡片补 `seg.target.dynamic`
  （"目标由变量决定，卡片无法命名"）；若这次是预演后的重试，改用 `seg.target.listed`
  （"目标由变量决定，见上面的只读清单"）。目标段不再整段消失。
- **quiet 不受影响**：`decideQuiet` 只接受单语句命令（`multi-statement` 直接否），单语句下"最坏"就是它自己。
- 测试：facts 25 条、describe 17 条；全套 12 文件 241 条 0 fail。
- 仍未做：有界命令头（P4 #7）；`apply_patch` 之外的插件自定义 shell 工具参数形状（未知）。
